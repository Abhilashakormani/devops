HOW IT WORKS

How It Works

A simple timeline explains the automated delivery path from a developer push to a live website.

1

Developer Pushes Code

A developer makes a change and pushes it to GitHub.

↓
2

GitHub Repository Receives Changes

The repository gets the new commit and stores the updated files.

↓
3

GitHub Actions Starts Automatically

The workflow runs as soon as the push reaches the main branch.

↓
4

Application Is Validated and Tested

Simple checks confirm that the website files and Docker setup are present.

↓
5

Docker Image Is Built

The static website is packaged into a lightweight Nginx container image.

↓
6

Docker Image Is Pushed to Docker Hub

The image is published using GitHub Secrets for secure login.

↓
7

Render Deploys the Application

Render serves the app as a public web service using the Docker setup.

↓
8

Updated Website Goes Live

The new version becomes available to anyone visiting the live URL.

TECHNOLOGIES USED

Technologies Used

Only lightweight, beginner-friendly tools are used so the project stays easy to explain and maintain.

HTML

Structures the content and sections of the website.

CSS

Creates the modern layout, colors, spacing, and responsive design.

JavaScript

Adds smooth navigation and small interface interactions.

Git

Tracks changes and supports version control for the project.

GitHub

Hosts the code repository and triggers the automation workflow.

GitHub Actions

Runs the automated build, test, and Docker push pipeline.

Docker

Packages the website into a portable container image.

Docker Hub

Stores the built Docker image in a registry.

Render

Deploys the application as a live web service.

ABOUT THIS PROJECT

About This Project

This project demonstrates a DevOps-based automated CI/CD workflow for deploying a web application. Whenever new code is pushed to GitHub, GitHub Actions automatically performs the required validation and testing steps, builds a Docker image, pushes the image to Docker Hub, and enables deployment through Render.

Objective: Reduce manual deployment effort and demonstrate an automated software delivery pipeline.
